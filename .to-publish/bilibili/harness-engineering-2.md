# Harness 怎么落地:从 OpenAI 100 万行到个人最小方案(下篇·实战)

> 直接从博客搬,已优化为 B 站长文风格

上篇讲了 Harness 是什么、为什么需要,本篇讲**怎么搭**。

大厂实践分两派:
- **OpenAI 派**:工程治理导向 — 5 个月 100 万行,靠自动 Linter 闭环
- **Anthropic 派**:质量评估导向 — Planner + Generator + Evaluator 三 agent 独立协作

## 一句话定论

> **模型决定上限,Harness 决定能不能落地。** 个人最小 Harness = 远程服务器 + Dev Container + Git Worktree + Oxidize。

## OpenAI 实战:5 个月 100 万行

**实验背景**:2025-08 启动,用 AI 从零写真实生产软件,5 个月 → ~100 万行代码,团队 3 → 7 人,**效率约为纯人工 10 倍**。

OpenAI 的优化点归为三类:

### ① 信息获取与整理

- AGENTS.md 压缩到 ~100 行当目录,文档分门别类放仓库、用到哪块看哪块
- 强制把重要决策/约定搬进代码仓库 → **仓库成为唯一事实来源**

### ② 验证与反馈

- **Chrome DevTools 接入** → Codex 自己截图、看 DOM、模拟用户操作,验证 UI 后原地修复
- 完整可观测性栈(日志/指标/链路追踪)
- 架构分层 + **Linter/测试自动闭环**:

```
Agent 生成代码 → Linter/测试 报错 → 报错发回 Agent → 修改 → 再检测 → 全部合规
     ↑_______________________ 自动闭环(无人工介入)______________________↓
```

### ③ 技术债清理

- 后台 Codex 任务定期扫描代码库,自动修改偏离规范处并提交

**OpenAI 灵魂观点**:"Human directs, agents execute" — 人类掌舵,Agent 干活。

## Anthropic 实战:Planner + Generator + Evaluator

**核心两点:任务规划 + 质量评估**。

### Full Harness vs Solo(Anthropic 实测)

| 维度 | Solo(单 Generator) | Full Harness(Planner+Generator+Evaluator) |
|------|------|--------------|
| 耗时 | 20 分钟 | 6 小时 |
| 花费 | $9 | $200 |
| 效果 | 布局不合理、bug 多,基本没法用 | 布局与逻辑达到可用水准 |

> 精雕细琢有代价:"考 60 分复习三天,考 90 分得复习一个月。"

**质量评估关键洞察**:Agent 自评是"王婆卖瓜自卖自夸" → 必须有**独立 Evaluator** 评估产出(第三方视角更客观)。

## 花园老师 6 层架构(系统层)

| 层 | 核心问题 | 关键设计 |
|----|---------|----------|
| 1️⃣ **Context 治理** | 模型看到了什么? | 角色目标 + 信息裁剪 + **结构化信息组织** |
| 2️⃣ **工具系统** | 模型能做什么? | 给什么工具 + 何时调用 + 工具结果怎么提炼后喂回 |
| 3️⃣ **执行编排** | 下一步该做什么? | 把步骤串成**轨道** |
| 4️⃣ **记忆和状态** | 模型知道做到哪了? | 三类分开管:任务状态 / 中间结果 / 长期记忆 |
| 5️⃣ **评估和观测** | 知道自己做得好不好? | 独立评估 + 自动测试 + 日志指标 + 错误归因 |
| 6️⃣ **约束校验失败恢复** | 失败了怎么办? | 约束 + 校验 + 恢复(重试/切入/回滚) |

花园老师核心洞察:**"修复方案从来不是让 agent 更努力一点,而是确定它缺了什么结构性的能力。"**

## 轩辕的 6 层防护网(实现层)

输入过滤 / 格式清洗 / 参数校验 / 工具调用 / 输出过滤 / 错误重试 + 硬编码兜底。

> 核心原则:**"能用代码卡住的事儿,就千万别只在提示词里面写。"**

## 个人最小 Harness(起步方案)

| 组件 | 作用 | 工具 |
|------|------|------|
| **远程服务器** | AI 在你合上笔记本后还能继续干活 | 阿里云/腾讯云学生机,Tailscale 连回家 |
| **Dev Container 沙盒** | 每个任务一个独立 Docker 盒子 | Docker + VSCode Remote |
| **Git Worktree** | 同一项目开多个分支,多 AI 同时干不同的事 | Git 内置 |
| **基本 Lint** | 格式 + 风格检查 | ESLint / Prettier / Ruff |
| **自动化测试** | 每个改动必须带测试 | pytest / vitest / jest |

## Oxidize Harness(让 AI 自己磨快)

> "你今天干活慢在哪里?缺什么工具?什么权限没给?列出优化方案。"
> 人审阅后执行 → AI 明天干活更快。

**LangChain 量化证据**:**仅通过改造 Harness,自家智能体从榜单 30 名开外拉到前 5**。

## 4 条核心原则

1. AI 审核 + 人验收 / 独立评估
2. 每次改动自带测试
3. 持续迭代 Harness 本身(Oxidize)
4. 个人最小起步,不要全抄大厂

## 一句话总结

> **Harness 是工程,不是神迹。** 模型没变,只是 Harness 改了 — LangChain 30 → 前 5 是最好的证据。**剩下的就是动手搭、跑、迭代。**
