## 引子:FDE 不是"高级实施",是"会写代码的业务翻译官"

上一篇 [FDE 概览](/blog/fde-overview-front-deploy-engineer) 我们讲了 FDE 是什么、Palantir 起源、2026 为什么爆发。

这一篇讲**实操**。两个问题:

1. **作为工程师,过去 6 个月你该做什么才能转型 FDE?**
2. **作为 FDE,你一天 / 一周的工作节奏是什么?**

FDE 不是"高级实施工程师"(凤德 高级实施岗),也不是"AI 工程师",是**会写代码的业务翻译官**。EY 报告里说 FDE 工作时间 30-40% 是沟通 + 会议,纯写代码只占 50-60%。**沟通能力差的人,技术再强也做不好 FDE**。

**重要原则**:本文按"**MVP 主义 + 拿来主义**"展开。所有工具都用现成的,所有技能都按"**6 个月转型**"节奏。

---

## 二、工程师转型 FDE 的 3 个硬动作

从普通工程师(后端 / 前端 / 算法)转型 FDE,**不是学一堆新技术**,而是**调整工作模式 + 补 3 个新能力**。

### 硬动作 1:每季度做 1 次"客户现场模拟"

**目的:理解"客户在想什么",不只是"代码怎么写"**

具体做法:
- 找 1 个朋友 / 同事,假装是你的甲方
- 他们说出"模糊需求"(例:"我们想要更聪明的客户管理")
- 你要在 30 分钟内,**不写一行代码**,拆解出 5 个具体的子需求 + 每个子需求的 ROI
- 这个练习每月做 1 次,持续 6 个月,你会发现你的"翻译速度"显著提升

### 硬动作 2:每季度学 1 个行业的"商业语言"

**目的:理解行业,不只是技术**

按 2026 年 FDE 招聘最多的 4 个行业,选 1 个深挖 6 个月:
- **金融**:信用评分 / 反欺诈 / 合规审计
- **医疗**:电子病历 / 诊断辅助 / 临床决策
- **制造**:供应链 / 库存优化 / 设备预测维护
- **零售**:推荐系统 / 库存周转 / 客户分层

每个行业的"商业语言"是看这家公司的年报 / 招股书,不是看技术文档。**理解"客户怎么赚钱",才能拆解"AI 怎么帮客户赚钱"**。

### 硬动作 3:做 1-2 个"非工作项目"展示业务能力

**目的:简历上能讲清"我做过什么"**

传统工程师的简历是"我用什么技术 / 我做了什么项目"。FDE 的简历应该是"**我帮什么客户解决了什么问题**"。

推荐项目:
- 给朋友的创业公司做 1 次 AI 集成(免费,但写客户成功故事)
- 在 Anthropic / OpenAI 开发者社区帮客户调试 1-2 个项目(展示"我能为客户服务")
- 在 GitHub 开源 1 个"AI 部署产品演示仓库"(展示"我能交付")

**6 个月后你的 LinkedIn 应该是"AI 工程师 + 业务翻译"的复合画像**。

## 三、FDE 一天的工作流(典型一天)

FDE 没有"标准一天",每个客户 / 每家公司不同。但有一个**共通节奏**:

```
07:30 起床 / 通勤(路上过客户前一天的工作记录)
09:00 客户早会(15-30min):今日交付目标 / 阻塞 / 需求变更
09:30 需求拆解(1h):把"模糊需求"拆成"可执行子任务"
10:30 代码 / 部署(2.5h):写代码 + 部署 + 调试
13:00 午饭
14:00 客户同步(30min):Demo / 反馈 / 调整
15: 文档(30min):写交付文档 + 给客户的下一步建议
17:00 内部 Sync(30min):跟自己公司产品团队同步,沉淀"可产品化"的需求
18:00 文档(30min):写交付文档 + 给客户的下一步建议
18:30 复盘(30min):今天做对了什么 / 做错了什么
19:00 下班(或 22:00 if 加班)
```

### FDE 一天的 5 个特点

1. **客户早会是核心**:不是"打卡会议",是"今日目标对齐",没早会一天都白干
2. **需求拆解 ≥ 1 小时**:这是 FDE 跟普通工程师的最大区别 — FDE **不接需求,拆需求**
3. **客户同步 ≥ 30 分钟**:每半天跟客户确认一次方向,避免"做完发现不是客户要的"
4. **内部 Sync ≥ 30 分钟**:这是 Palantir Delta/Echo 模型的核心 — 一线需求方向是"内部产品"的输入
5. **文档 + 复盘 ≥ 1 小时**:FDE 一天的核心输出不是代码,是"**客户成功路径**"

### FDE 一天的 3 个雷区

1. **跳过客户早会** — 早会是对齐节奏的,跳过就脱节
2. **埋头写代码不看客户** — FDE 不是"驻场程序员",是"驻场翻译官"
3. **不写复盘** — 不复盘 = 不成长 = 下次还踩同样的坑

## 四、FDE 一周的工作流

一周的节奏是 FDE 真实工作的"周而复始":

| 日 | 主题 | 关键动作 |
|---|---|---|
| **周一** | 客户现场 | 9 点到客户现场,跟客户团队一起开 review 一周计划 |
| **周二** | 开发 + 部署 | 主力开发日,集中写代码 + 部署 + 调试 |
| **周三** | 客户 Demo | 中期 Demo,客户上午拿改了一半的系统过反馈 |
| **周四** | 改进 + 沉淀 | 根据客户反馈改进,把"可复用"部分抽成 L1 |
| **周五** | 周复盘 + 下周计划 | 跟客户 + 内部 sync,复盘一周 / 计划下周 |

### 周节奏的 3 个原则

1. **周一 + 周三必须见客户** — 任何一周错过这两天,客户关系就开始出问题
2. **周二 + 周四是高产出日** — 不要在客户现场开会打断,把"实操"集中在这两天
3. **周五复盘 = 给自己 + 客户 + 公司三方的反馈** — 缺一不可

### 远程 / 驻场的差异

FDE 不一定要驻场,**远程 + 关键里程碑现场**是 2026 主流模式:

| 模式 | 比例 | 适合客户 |
|---|---|---|
| **驻场** | 100% | 大型政企 / 长周期 / 高合规客户 |
| **混合** | 50% | 中型客户 / 中周期 / 关键里程碑现场 |
| **远程为主** | 20% | 小型客户 / 短周期 / 远程协作流畅 |

**Palantir FDSE 现在大部分是混合模式**:每周 1-2 天现场,其他远程。

## 五、FDE 必备技能栈(13 项)

FDE 不是 ad-hoc 工程师,**13 项技能按重要性分 3 层**:

### 第 1 层:核心工程技能(必须熟练,6 项)

**1. Python**

- FDE 主力语言,必备
- 学习路径:[Python 入门 → 进阶 → 数据处理(PandasNum) → API 框架(FastAPI / Django)]
- 资源:[Real Python](https://realpython.com) / [FastAPI 文档](https://fastapi.tiangolo.com)

**2. SQL**

- 客户数据查询必备
- 95% 客户数据存在 SQL 数据库
- 资源:[SQLBolt](https://sqlbolt.com) / [Mode SQL 教程](https://mode.com/sql-tutorial/)

**3. Docker**

- FDE 部署必备
- 客户环境从 Docker 起步最简单
- 资源:[Docker 官方教程](https://docs.docker.com/get-started/)

**4. REST API / Webhook**

- 客户系统集成必备
- 95% 系统集成走 REST API
- 资源:[REST API 设计指南](https://restfulapi.dev/) / [Webhook 入门](https://webhook.site/)

**5. CI/CD(GitHub Actions / GitLab CI)**

- 客户代码部署必备
- FDE 每天至少 1 次部署
- 资源:[GitHub Actions 文档](https://docs.github.com/en/actions)

**6. 云平台基础(AWS / GCP / Azure)**

- 客户环境部署必备
- 至少要会 1 个云平台
- 资源:[AWS 官方教程](https://aws.amazon.com/getting-started/)

### 第 2 层:AI 工程能力(2026 FDE 必备,4 项)

**7. Agent / Skills 编排**

- FDE 必须能把多个 AI 任务串成工作流
- 资源:互链见 [Agent Skills 入门](/blog/agent-skills)

**8. Context Engineering**

- FDE 必须能让 AI 在多步任务里保持任务一致性
- 资源:[Context Engineering 实战](/blog/context-engineering)

**9. Vibe Coding**

- FDE 在客户现场经常需要快速搭原型
- 资源:[Vibe Coding 学习路线图](/blog/vibe-coding-learning-roadmap)

**10. Harness Engineering**

- FDE 必备的工作流闭环能力
- 资源:[Harness Engineering 第一阶](/blog/harness-engineering-1)

### 第 3 层:业务沟通能力(FDE 跟普通工程师的差距,1 项)

**11. 技术语言 ↔ 商业语言翻译**

- 客户不是工程师,不会看代码
- FDE 必须能把"系统延迟 200ms"翻译成"客户下单慢 1 秒"
- 训练方法:每季度做 1 次"客户现场模拟"(见硬动作 1)

### 第 4 层:行业深度(加分项,2 项)

**12. 1 个行业的商业流程**

- 例:金融行业要懂信用评分 / 反欺诈 / 合规审计
- 推荐:跟 1 个行业深挖 6 个月

**13. 1 个行业的法规合规**

- 例:医疗行业要懂 HIPAA / GDPR
- 推荐:跟 1 个行业深挖 6 个月

## 七、FDE 转型的 6 个月路线图

按 Neo 后端零基础 + MVP 主义,**6 个月从工程师到 FDE** 的最小可行路线:

| 月份 | 重点 | 关键里程碑 |
|---|---|---|
| **第 1 月** | Python + SQL 强化 | 能用 Python 写 REST API |
| **第 2 月** | Docker + CI/CD | 能把 Python API 容器化 + 自动部署 |
| **第 3 月** | AI 工程能力 | 掌握 Agent Skills + Context Engineering |
| **第 4 月** | 客户沟通 | 做 4 次"客户现场模拟"(每季度 1 次) |
| **第 5 月** | 行业深度 | 选 1 个行业深挖(看年报 / 招股书 / 行业报告) |
| **第 6 月** | 项目交付 | 完成 1-2 个"非工作项目",简历可写 |

**6 个月后,你可以投 FDE 岗了。**

## 八、FDE 跟 OPC 的实战连接(系列呼应)

上一篇 [OPC 实操](/blog/opc-practice-guide) 讲"怎么开公司",本篇讲"怎么当 FDE"。两者是**同一硬币**:

- **OPC 创业前期**:你很可能先在大厂做几年 FDE,**攒够客户资源 + 业务理解 + 工程能力**,再开公司
- **FDE 服务客户时**:你服务的客户可能就是 OPC,**理解 OPC 怎么想**,能帮你精准对接

**实战连接**:如果你已经在 OPC 集群(鸿鹄汇等),你可以**主动请缨做 OPC 集群里其他企业的 FDE**。这比在大厂里等分配更有意思,还能直接攒 OPC 客户资源。

## 总结:FDE 是 2026 年工程师转型的最佳选择

三个判断:

1. **FDE 是稀缺岗位**(供需比 1:2.7,人才缺口 60%+),转型难度比纯 AI 研究低很多
2. **FDE 收入比传统工程师高 30-50%**(美国中位 21.5 万美元年薪,顶配 50 万美元+)
3. **FDE 是 AI 时代工程师的"复合身份"**:会技术 + 会业务 + 会沟通 = 不可替代

三个不要:

1. **不要只学技术**:FDE 不是"AI 工程师",业务沟通是关键
2. **不要等公司分配 FDE 岗**:大厂 FDE 招聘竞争激烈,建议先做 OPC 集群的"野路子 FDE"
3. **不要做 FDE 1 年就跳**:FDE 的"客户资源 + 业务理解"需要 2-3 年沉淀
