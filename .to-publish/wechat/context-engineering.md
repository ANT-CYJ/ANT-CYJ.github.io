## 仓库比喻

> Prompt 决定**怎么问**客户
> Context 决定**带什么资料**去拜访
> Harness 决定**怎么管理整个拜访流程**

## 一句话定论

> **Context Engineering = 精心设计放进模型上下文窗口的内容,让模型在正确时机看到正确信息。**

## 三层关系(层层递进,层层包含)

| 层级 | 大白话 | 典型手段 |
|------|--------|----------|
| **Prompt** | 怎么问问题 | "帮我给橘色小猫起名,两个字" |
| **Context** | 怎么给信息 | 压缩 / 检索 / 渐进式披露 |
| **Harness** | 怎么搭系统 | 权限管控 / 工具管理 / Linter 闭环 |

**Prompt ⊂ Context ⊂ Harness**(包含而非替代)。

## Context 8 个组成部分(大部分人只知道 1 个)

很多人以为"Context = 对话历史"。**错**。对话历史只是 1/8。

完整 8 部分:用户输入 / 历史对话 / 检索结果 / 工具返回 / 任务状态 / 中间产物 / 系统规则 / 安全约束。

## 6 个核心方法

**1. 上下文压缩** — 摘要替代冗长内容(代价:信息丢失)

**2. 上下文重置**(⭐ 最激进) — **换全新 agent 交接工作**。类比"内存泄漏 → 重启进程"。**DeepSeek Harness 的"换脑"就用了这个**。

**3. 动态检索 RAG** — 按需搜资料,不一次性塞

**4. 渐进式披露** — AGENTS.md 100 行当目录,不一次全给

**5. 信息裁剪** — 不是越多越好,是越相关越好(100 行 > 50KB)

**6. 结构化组织** — 5 段式(角色/任务/历史/证据/工具),模型能快速定位

## 4 条原则

1. **8 件事都要管** — 别只盯对话历史
2. **宁少勿杂** — 信息密度 > 信息量
3. **结构化优先** — 5 段式固定
4. **Context Reset 备好** — 换 agent 比硬撑有效
